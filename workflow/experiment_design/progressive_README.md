## 本次只做第一步的校准模式

用户要求先审第一步再推进时，初始化加`--first-step-only`，执行`understand-only`。此模式只输出逐篇作者解释、物理过程理解、实验/分析支持、来源与边界，schema不含联系问题或查询；最多一次模型调用，完成后状态为`awaiting_user_calibration`，后续检索/联系/交接命令会被阻止。不是新增常规审批要求，而是落实本次用户明确指定的停点。用户校准后按其意见另行衔接，不能自动放行或因等待而重复第一步调用。

```powershell
python scripts/progressive_discovery.py init --run RUN_DIR --group-id GROUP_ID --paper-ids PAPER_IDS --first-step-only --token-ceiling 18000
python scripts/progressive_discovery.py understand-only --run RUN_DIR
```

此模式保留精确原文、来源ID、论文ID与读取层级，省去输入中重复的书目信息；完整书目和原始锚点仍保存在运行目录。常规完整路线仍按下文阶段执行。

## 科学步骤与交付

1. **理解作者解释，再核实验依据。** 从已经选定的大问题和既有逐篇资料进入，回连已有原文锚点。模型先说明作者实际上讨论的物理过程与语义对应理由，再说明实验、分析支持到哪里。术语是否出现不是判据；作者解释、实测、项目理解分别写。未读到原文或覆盖不足保留未知，不把摘要升级为原文，也不要求所有假说已经被证明才能继续。
2. **从解释差异提出联系问题，再查文献。** 对同类体系提出：不同解释能否共存、竞争、互补，是否因条件而改变贡献？也允许不相容或尚无法联系，不强求统一。先保留未排序的联系问题、查前判断和改变/停止条件，再逐题以同等规则检索；回读后判断已有研究连到了哪一步、给出哪些影响因素、还有什么值得研究。出现新证据时可修正第一步的理解，保存前后判断和谱系。
3. **由文献连接依据推导变量，再回读方法。** 第三步选择操控前，区分已知影响因素、文献采用的操控和本题可选操控；比较各路径与认识目标的对应及附带变化，再说明选用理由。只有一条有依据的路径时可保留，但须说明，不为凑数虚构替代。不能直接照搬文献操控，也不强制同分异构体、梯度或其他固定形式。 从具体操作进一步归纳“改变何种结构、组成/含量或物理条件→影响哪个过程→回答什么认识问题”，不止停留在换盐、换溶剂、改配比等操作名称。禁止预设模板不等于回避经证据推导出的结构对照或浓度/配比梯度；变量主线形成、选择理由充分、具体方案完成分别评价，不因操控与旧版同名或后续参数未定就否定已有推导。具体结构差异、梯度口径/范围/点数与方法在后续设计中选择，不将结构＋梯度固定为通用答案。 每条`factor_links`用`control_options`保留最多3条有依据路径、用`selection_reason`说明选择；允许仅1条，不强造多选。认识目标→操控比较与选择→变量推导→方法回读按此顺序执行。先明确想增加哪种认识，再写“文献关系→影响因素→可操控变量→应减少的其他变化→外推边界”。实验形式由这条关系决定。然后指明要回读的方法文献与待核问题，检查核心方法是否能判别、是否多数实验室能实施。所有候选的方法补证完成后才比较具体问题；方法依据不足保留明确缺口，不以常见设备名称代替有效测量。

三步之后才进入具体分子、配方与实验参数选择，以及生成—审查—修订设计。现有G1/G2与有限停止继续适用，不增加人工审批。普适关系是可能的研究目标，不是每题必须产出的结论。同分异构体、浓度/配比梯度不作为输入模板、必选变量或评价标准；少量匹配对照的选择必须能追溯到本题的文献推导。

## 程序顺序

```text
init：固定上游问题/范围，完整保留摘要，加载有来源的原文锚点并记录遗漏
→ understand：理解解释与核证；然后形成未排序的联系问题和检索任务
→ search-links：全部联系问题补证，OpenAlex＋DOI回本地正文/SI或公开原文
→ connect：判读查新联系、更新理解、推导变量、提出方法回读任务
→ read-methods：逐题回读指定方法文献＋方法检索
→ handoff：冻结事实输入与真实上游回执；此时尚未完成方法语义审查
→ init-progressed：传入已有下游设计器
→ synthesize：先判方法依据与普遍可实施性，再比较候选，形成设计依据
→ criticize → design：沿用有据干预、核心观测和审查门槛，具体选分子/配方/方法
```

三个科学步骤不机械等于三次模型调用。为控制成本，第一步核证与第二步提出问题合在 `understand`；第二步检索后的判读与第三步变量推导合在 `connect`；方法回读后的判断复用原 `synthesize`。正常上限是上游2次＋下游3次，不要求跑满；检索与定向读取是程序操作，不另加模型评委。所有模型调用共享同一可观测input＋output预算，下游带入已用token；失败无回执的消耗另记未知。预算是调用前预检，不是服务端硬上限；不自动抬高、重抽或为了非零续跑。

## 使用方式

以下为命令模板，不是已经运行的科学任务。`GROUP_ID`、`PAPER_IDS`由实际授权范围替换；未指定paper-ids会取该上游组全部既有篇目，初始化本身不调用模型。

```powershell
python scripts/progressive_discovery.py init --run RUN_DIR --group-id GROUP_ID --paper-ids PAPER_IDS --max-candidates 2 --token-ceiling 60000
python scripts/progressive_discovery.py understand --run RUN_DIR
python scripts/progressive_discovery.py search-links --run RUN_DIR
python scripts/progressive_discovery.py connect --run RUN_DIR
python scripts/progressive_discovery.py read-methods --run RUN_DIR
python scripts/progressive_discovery.py handoff --run RUN_DIR
python scripts/inspiration_design.py init-progressed --run RUN_DIR/downstream --handoff RUN_DIR/handoff.json
python scripts/inspiration_design.py synthesize --run RUN_DIR/downstream
python scripts/inspiration_design.py criticize --run RUN_DIR/downstream
python scripts/inspiration_design.py design --run RUN_DIR/downstream
```

本机可用解释器：`C:/Users/Laylaaali/.local/bin/python3.14.exe`。`--transport http_no_retry`仅在既有网络诊断适用时使用；只复用现有ChatGPT登录，无付费API回退，不操作前台。数据/目的地授权与平台审批继续遵守，不因本文件而扩权。

初始原文取已有逐篇关系中的精确段落锚点，默认总字符上限16000，可显式设置 `--primary-char-limit`。完整摘要不截断；未加载的段落及原因写入 `coverage.json`。此选择只提供核读入口，不代表全文覆盖或语义已经正确。模型可以保留partial/unread，并在后续补证中更新判断。

检索保留完整响应、查询、失败和访问层级；索引命中不等于全文核读。方法回读使用单独的 `method_source_refs`，不默认候选第一篇背景引用就是方法来源。检索服务401/403/429停止状态从联系检索传到方法检索，不以切换子目录重置。公开正文取得与模型读过分开报告。

需要人工定向补充来源时，分别用 `supplement_before_selection.json` / `supplement_methods.json`，含 `evidence` 和 `search_log` 数组；保留实际工具回执和读取层级。同ID不同正文/DOI会被拒绝，不能覆盖旧证据或把引用补齐当科学结论。原文窗口可能遗漏方法，不能自动写成可实施。

## 实现与验收边界

- 程序防止跳过联系检索和方法回读、漏掉某个候选的补证/处置、丢失谱系、只凭摘要声明已核实实验支撑、变量没有来源推导以及下游预算清零。
- 新入口不把历史具体答案传给科学模型。原小试/旧运行目录及manifest保持原样；导入上游时保留真实receipt，不伪造 `branches` 模型调用。
- 结构检查不认证语义、因果、创新或测量有效性；这些仍由实际科学判读及审查承担。
- 离线测试使用临时目录中的明确合成回执、模拟检索和模拟模型输出，覆盖真实编排接口；不能说已完成独立科学角色运行或端到端科学验证。
- 旧 `inspiration_design.py init` 路线保留用于历史开发兼容；当前三步推进从新入口开始，不再从摘要直接跳到具体候选方案。

## 2026-11-17：结构路线与新增判别修正（v1.4 / v0.8）

改变供体原子、官能团、连接方式或相对位置均可作为有依据的结构路线，不因改变官能团否定，也不强制同分异构体。选具体体系前对照最近邻原文已覆盖的结构、组成范围、响应/状态及解释边界；仅有方法窗口时不得把未读到当作未研究。先判断既有数据能否回答，再明确剩余待判关系、竞争解释的不同预期及新对照为何能增加原文没有的区分能力。同材料/方法允许承载新判别，形式相似不自动淘汰；换分子、改统计、减少点数或缩小覆盖不自动增加认识。不能把原研究的缩水复测包装为最小判别方案。精简后复核剩余设计仍否回答原问题；若只能得到更弱的已知结论，同步改变目标及处置，不保留原创新标题。沿用现有认识增量/准入/审查环节及known/hold/none，不增加审批或模型评委，也不要求候选假说先被证明。

生产`DESIGN_INCREMENT_RULES`在recombine、critic、revise_design共用，三步下游继承；connect补充结构路线与主线/实验价值区别。沿用已有字段，无新增模型调用。冻结局部试跑脚本和原始结果不回写；未来适配须显式复用共享规则并保留正式交接或开发适配身份。当前仅提示接入和离线验证，不宣称科学效果已验证，不重跑前三步。

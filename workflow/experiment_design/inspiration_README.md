顺序为 `init → generate → retrieve → synthesize → criticize → design → verify`。每个命令都指定同一个 `--run` 独立输出目录。初始目录不可覆盖；阶段不自动重抽。四次模型调用分别为 branches、recombine、critic、revise_design，均保存独立 CLI 上下文、输入、schema、原始输出和实际用量。独立上下文审查仍是同一模型，不称外部专家独立验证。

初始范围为 G01 的全部 59 篇已有完整机制摘要及体系边界，不是重新提取全文，也不是 313 篇全库发现。各分支最多两条核心引文；补证器回查全部种子原文，OpenAlex 每查询最多三条。题录、摘要、正文窗口和完整核读须区分，自动窗口可能抓到引言，必要时补相关结果和方法而不改写旧回执。

OpenAlex 或公开正文失败时，当前版本接受人工调用网页工具所得的 `web_supplement.json`，格式为 `evidence` 与 `search_log` 数组；证据含 id、doi、kind、text、access_note，网页证据另有 url。审查后补证用 `review_supplement.json` 同一格式。必须保存查询、原始网页回执和访问限制。该接口已接入，网页搜索回退尚非自动执行。补证的原始文件与段落选择由父会话完成，不能声称完全无人干预。

程序校验来源 ID、全部分支处置、全部查询判断变化、审查目标、模型上下文唯一性和冻结文件哈希；这些不认证语义、因果或创新。六项针对性测试覆盖完整范围、分支处置、证据合并冲突、未成熟题不生成矩阵及修订ID的父节点约束。预算按实际回执累计，100000 是本次防失控上限而非消耗目标；调用前有保守预留。父会话和工具无统一 usage 时单独记未知。

本次实跑版本迁移到v0.3：v0.2仅收敛设计输入，保留所选题审查和全部相关证据，去除其他候选审查正文及重复检索列表；v0.3接受N1-R1这类明确修订后缀，另存父节点谱系，不改模型原始输出。迁移前代码、manifest及理由保存在运行的migrations目录，未重抽科学答案。

## 2026-11-17：结构路线与新增判别修正（v1.4 / v0.8）

改变供体原子、官能团、连接方式或相对位置均可作为有依据的结构路线，不因改变官能团否定，也不强制同分异构体。选具体体系前对照最近邻原文已覆盖的结构、组成范围、响应/状态及解释边界；仅有方法窗口时不得把未读到当作未研究。先判断既有数据能否回答，再明确剩余待判关系、竞争解释的不同预期及新对照为何能增加原文没有的区分能力。同材料/方法允许承载新判别，形式相似不自动淘汰；换分子、改统计、减少点数或缩小覆盖不自动增加认识。不能把原研究的缩水复测包装为最小判别方案。精简后复核剩余设计仍否回答原问题；若只能得到更弱的已知结论，同步改变目标及处置，不保留原创新标题。沿用现有认识增量/准入/审查环节及known/hold/none，不增加审批或模型评委，也不要求候选假说先被证明。

生产`DESIGN_INCREMENT_RULES`在recombine、critic、revise_design共用，三步下游继承；connect补充结构路线与主线/实验价值区别。沿用已有字段，无新增模型调用。冻结局部试跑脚本和原始结果不回写；未来适配须显式复用共享规则并保留正式交接或开发适配身份。当前仅提示接入和离线验证，不宣称科学效果已验证，不重跑前三步。
